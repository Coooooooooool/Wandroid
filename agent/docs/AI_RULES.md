# Agent Rules

## 1. 角色定义

Agent 的职责是：

- 读取任务文档
- 在既定架构约束下实现任务
- 更新必要文档与任务状态
- 对不明确内容进行风险提示或暂停升级

Agent 不是需求决定者，也不是自由发挥的代码生成器。

## 2. 执行原则

- 先读文档，再动代码
- 先确认任务边界，再修改实现
- 一次只完成一个明确任务
- 改动必须可验证、可追踪、可回滚

## 3. 必须遵守的输入顺序

开始任何开发任务前，Agent 必须按以下顺序读取上下文：

1. `agent/docs/PROJECT_SPEC.md`
2. `agent/docs/MODULES.md`
3. `agent/docs/API_SPEC.md`
4. `agent/docs/WORKFLOW.md`
5. `agent/tasks/TASK_QUEUE.md`
6. 对应任务文件

如果任务涉及登录态、接口约束或分页差异，必须额外核对 `WANANDROID_API_CHECKLIST.md`。

## 4. 允许的行为

- 实现当前任务范围内的代码
- 修复当前任务直接导致的编译问题
- 更新与本任务直接相关的文档
- 补充必要的状态说明、错误处理和验收记录

## 5. 禁止的行为

- 未经任务文档授权，擅自新增大模块
- 未经确认，跨多个无关功能做顺手修改
- 跳过 Repository 直接在 UI 调接口
- 未更新任务状态就声称任务完成
- 未确认分页规则就直接写死页码逻辑
- 未确认登录态处理就直接在页面拼 Cookie 或临时状态

## 6. 必须暂停并升级给用户的场景

出现以下情况时，Agent 必须停止直接实现并明确说明原因：

- 需求边界不清晰，存在多种互斥方案
- 任务要求跨越多个模块且无明确拆分
- 接口文档与真实返回明显冲突
- 现有目录结构无法承载改动，需要架构调整
- 出现与当前任务冲突的用户本地改动

## 7. 任务完成定义

Agent 只能在以下条件都满足后标记任务完成：

- 代码改动完成
- 与任务相关的文档已同步
- 验收项逐条满足
- 已记录风险或遗留项
- `TASK_STATE.md` 中状态已更新为 `done` 或 `review`

## 8. 输出要求

Agent 对每个任务的输出至少应包含：

- 实现内容
- 涉及文件
- 验证方式
- 已知风险
- 下一步建议

## 9. 文档维护要求

以下变化必须由 Agent 主动同步：

- 新增接口：更新 `API_SPEC.md`
- 新增任务：更新 `TASK_QUEUE.md`
- 任务状态变化：更新 `TASK_STATE.md`
- 模块边界变更：更新 `MODULES.md`

## 10. 质量底线

- 优先修根因，不做表面补丁
- 不引入与当前阶段无关的复杂抽象
- 命名保持稳定、直接、可读
- 文档与实现不一致时，必须指出而不是忽略
