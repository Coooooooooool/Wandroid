# Task 001 - 首页公开数据接入

## 1. 背景

首页公开数据链路可以同时验证以下基础能力：

- 网络层是否可用
- 通用响应是否可解析
- 分页是否可工作
- UI 状态流是否合理

因此它是整个项目的首个基础任务。

## 2. 目标

完成首页公开数据的最小闭环：

- 首页文章列表
- 首页置顶文章
- Banner
- 常用网站
- 搜索热词

## 3. 范围

本任务包含：

- 定义首页相关 API
- 建立首页相关 DTO 和领域模型
- 建立首页 Repository
- 建立首页 ViewModel 和 UI State
- 页面展示基础列表和首屏附属数据

## 4. 非范围

本任务不包含：

- 登录
- 收藏
- 搜索结果页
- 体系、导航、项目模块
- WebView 文章详情页

## 5. 依赖

- `agent/docs/API_SPEC.md`
- `agent/docs/MODULES.md`
- 首页相关接口来自 `WANANDROID_API_CHECKLIST.md`

## 6. 实现提示

- 首页文章分页从 `0` 开始
- 置顶文章建议由 Repository 与第一页数据统一编排
- Banner、热词、常用网站建议并行加载
- 要明确区分首屏整体加载态和列表分页加载态

## 7. 验收标准

- 能成功请求首页文章第一页
- 能加载并展示 Banner
- 能加载并展示热词
- 能加载并展示常用网站
- 下拉刷新能重置首页数据
- 加载更多能继续请求下一页
- 错误态不会导致页面崩溃

## 8. 风险

- 首页聚合数据较多，容易把 UI 状态写乱
- 置顶文章与普通列表合并时要注意去重和顺序
- 分页状态若直接放 UI 层，后续搜索和项目列表可能难复用
